# The Theater

The Theater is a candidate consumer because its Astro blog is a real narrative publication surface generated by a collaborative fiction system.

It is valuable negative/positive evidence for editorial Cobogó work: shared reading grammar may apply, while its theatrical identity should remain substantially local.

## Project-surface evidence — 2026-08-16

The repository describes a distinctive production machine behind the publication: GitHub Actions plus Jules sessions coordinate character actors, story sessions and an Astro blog. The public home exposes part of that machinery through progressive disclosure — including a backstage route — while keeping the story and coverage as the primary reading surface.

Freshness is currently **negative evidence**, not proof of a healthy automation. Both README and home use present-tense claims that the heartbeat fires / something happens every 15 minutes, but the inspected repository head is still Stage Manager `heartbeat: round 563` (`6b1f364`, 2026-03-18), and recent Actions history inspected on 2026-08-16 showed Dependabot activity rather than current fiction-heartbeat runs. This does not prove whether the production is intentionally paused or operationally broken; it proves only that the public cadence claim is not currently supported by the inspected execution evidence.

Consumer issue [the-theater#278](https://github.com/franklinbaldo/the-theater/issues/278) tracks the product-local correction. Preserve the boundary: automation status can be progressively disclosed, but should not dominate the fictional reading surface.

For Cobogó, this is evidence for the experimental [Automation claim and observable freshness](../patterns/automation-observable-freshness.md) relation. A configured workflow, historical heartbeat commit and current successful execution are distinct evidence classes. The pattern does not imply a generic status component or change this consumer's `adoption_status`/`capabilities_used`.
