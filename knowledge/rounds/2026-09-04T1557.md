# Rodada — Cobogó: a API pública precisa ser uma escolha, não um reflexo dos arquivos internos

## O que estava errado ou faltando

O Cobogó permanece com avaliação de qualidade de 24 de 24 pontos: Clareza 4/4, Explicabilidade 4/4, Autonomia 4/4, UX 4/4, UI 4/4 e Confiança 4/4. Esta rodada não parte de uma tentativa de elevar nota. O problema é estrutural na forma como o próprio design system se apresenta a projetos e agentes.

A RFC 0003 foi incorporada nesta rodada pela #478 depois que CI, observação visual e GitGuardian ficaram verdes no commit atual da branch. Ela explicita uma direção já coerente com a governança opinionada: Cobogó deve começar por problemas e padrões visuais, reduzir abstrações sobrepostas e poder recomendar uma implementação tecnológica atual sem fingir neutralidade de suporte.

A PR empilhada #479 tentou transformar essa direção em inventário, mas ficou não incorporável depois do squash da #478. Isso é um impedimento mecânico da pilha, não motivo para abandonar conteúdo ainda útil. A rotina faz uma única recuperação mecânica reconstruindo o inventário a partir do `main` já atualizado.

D1, D2 e D3 permanecem 4/4 no estado atual e não há novo problema factual nessas dimensões. A dívida escolhida é de coerência da superfície de desenvolvimento: `package.json` publica `./components/*`, tornando a árvore empacotada importável mesmo quando `src/index.ts` tenta apresentar uma lista curada. Também há uma lista root plana de símbolos e uma paleta fixa pública que conflitam com a direção de gramática antes de componentes.

## Pré-registro imutável

Problema escolhido: a organização interna do pacote pode virar contrato público sem uma decisão explícita do Cobogó, aumentando escolha acidental e custo de compatibilidade.

Critério verificável desta rodada: produzir um inventário factual que identifique quais mecanismos ampliam a API pública e formule uma recomendação Cobogó com princípio, racional, contrato, critério observável, possibilidade explícita de exceção e condição de falsificação. A rodada não pode remover APIs nem fingir que a recomendação já foi validada por um projeto real.

A recomendação formulada é `public-api-is-curated`, inicialmente `opinionated`. Em português comum, isso significa que o Cobogó considera a posição correta e quer testá-la; ainda não há aplicação real bem-sucedida suficiente para chamá-la de validada.

## O que foi feito

Antes de escolher trabalho novo, a rotina reconciliou a #478. No commit `450cb35117b794d880cc29e3714fb3140081f872`, CI, observação visual e GitGuardian terminaram verdes; a PR estava incorporável e entrou por squash como `c6071be2ed1626c9017d4324080722f67fe461cd`.

Depois do merge, a #479 passou a apontar para `main` já contendo a RFC, mas permaneceu não incorporável. Em vez de forçar a branch antiga, o conteúdo útil do inventário foi reconstruído numa branch limpa baseada no novo `main`.

O inventário registra cinco fatos: o wildcard `./components/*` enfraquece a curadoria; o root API mistura famílias e detalhes de composição; `tokens` publica uma paleta concreta como se fosse foundation universal; a distribuição continua Svelte-first apesar da direção atual privilegiar Astro; e a documentação precisa separar gramática independente de framework de implementação recomendada.

Também foi criada `public-api-is-curated`: a recomendação diz que arquivos internos não devem se tornar API pública por conveniência de wildcard e preserva uma exceção explícita para ecossistemas em que imports profundos sejam deliberadamente parte do produto.

## O que ficou comprovado

A própria configuração atual do pacote é suficiente para comprovar o mecanismo escolhido: existe um export wildcard de componentes, enquanto `src/index.ts` mantém uma lista explícita menor. Isso mostra uma diferença objetiva entre a curadoria pretendida e o que o pacote torna importável.

A auditoria não prova ainda que fechar essa fronteira funciona melhor para um projeto real. Por isso a recomendação não é chamada de `validated` nem de `stable`.

## O que ainda falta

A branch limpa ainda precisa virar PR, passar pelos verificadores do commit atual e ser incorporada. A #479 antiga deve ser fechada como substituída apenas depois de existir uma sucessora explícita, para não perder o rastro do trabalho.

Nenhuma avaliação, ConsumerCard ou ranking deve mudar nesta rodada: não houve fato novo sobre a interface pública do Cobogó que justificasse alterar 24/24, e formulação interna não gera ponto acima do máximo.

## Por que a próxima rodada deve ou não voltar

Se a PR limpa for incorporada nesta rodada, o Cobogó não deve voltar apenas para repetir o inventário. O retorno será justificável quando houver uma aplicação concreta — por exemplo, uma PR que feche o wildcard, reorganize uma família pública ou teste a recomendação em um consumidor — ou quando aparecer evidência que contradiga a tese.

Se os verificadores impedirem a incorporação, a próxima rodada só deve voltar quando o estado deles mudar ou houver uma correção mecânica objetiva disponível.
