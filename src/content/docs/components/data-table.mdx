# Tabela de dados

Cobogó não possui mais um componente `DataTable` que recebe arrays e decide como interpretar cada coluna. O contrato compartilhado é o pattern `data-table`: o consumidor escreve a tabela HTML que representa seu domínio; Cobogó cuida de superfície, overflow, foco e ritmo visual.

## Demonstração

<div
  class="demo-container br-component-class"
  data-cobogo-pattern="data-table"
  tabindex="0"
  aria-label="Mestres do Modernismo Brasileiro"
>
  <table>
    <caption>Mestres do Modernismo Brasileiro</caption>
    <thead>
      <tr>
        <th scope="col">Nome</th>
        <th scope="col">Função</th>
        <th scope="col">Cidade</th>
        <th scope="col">Status</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td>Lina Bo Bardi</td>
        <td>Arquiteta</td>
        <td>São Paulo</td>
        <td><span data-cobogo-pattern="state" data-cobogo-state="success">Ativo</span></td>
      </tr>
      <tr>
        <td>Oscar Niemeyer</td>
        <td>Arquiteto</td>
        <td>Rio de Janeiro</td>
        <td><span data-cobogo-pattern="state" data-cobogo-state="success">Concluído</span></td>
      </tr>
      <tr>

## Uso

```astro
<div
  data-cobogo-pattern="data-table"
  tabindex="0"
  aria-label="Contratos encontrados"
>
  <table>
    <caption>Contratos encontrados</caption>
    <thead>
      <tr>
        <th scope="col">Contrato</th>
        <th scope="col">Objeto</th>
        <th scope="col">Status</th>
      </tr>
    </thead>
    <tbody>
      {rows.map((row) => (
        <tr>
          <td>{row.numero}</td>
          <td>{row.objeto}</td>
          <td>
            <span
              data-cobogo-pattern="state"
              data-cobogo-state={row.estadoVisual}
            >
              {row.status}
            </span>
          </td>
        </tr>
      ))}
    </tbody>
  </table>
</div>
```

## O estado pertence ao domínio

O antigo `DataTable` tinha uma regra embutida: uma coluna chamada `status` era reconhecida por nome e strings como `Ativo`, `Concluído`, `Pendente` e `Cancelado` eram convertidas automaticamente em cores/tokens.

Essa inferência desaparece. O consumidor sabe o significado de seus próprios estados e escolhe explicitamente `info`, `success`, `warning` ou `danger` quando uma codificação visual for apropriada.

Isso evita que Cobogó transforme palavras específicas de um produto em semântica global.

## Acessibilidade

- use `<caption>` para nomear a tabela visivelmente;
- use `scope="col"`/`scope="row"` quando aplicável;
- mantenha a ordem do DOM igual à ordem de leitura;
- quando a tabela puder rolar horizontalmente, o wrapper pode receber `tabindex="0"` e um nome acessível para que usuários de teclado alcancem a região de scroll;
- não use cor como único sinal de estado: o texto continua presente.

## Por que pattern e não componente

A estrutura de linhas, colunas, células, links, botões e estados pertence aos dados reais do consumidor. Um componente genérico precisaria inventar uma mini-linguagem de configuração para reproduzir HTML que já é mais expressivo e acessível.

Cobogó compartilha a **relação visual da tabela**; o consumidor mantém o **modelo e a marcação do domínio**.
