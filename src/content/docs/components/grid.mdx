O grid do Cobogó é uma **relação de layout**, não uma hierarquia de componentes. Use `data-cobogo-pattern="grid"` no elemento semântico que já existe na página e configure apenas as custom properties necessárias.

Não existem mais componentes `Grid` e `Column`. Isso evita criar wrappers Svelte apenas para escrever `display: grid`, `grid-template-columns`, `gap` e spans responsivos.

## Uso básico

```astro
<section
  data-cobogo-pattern="grid"
  style="--cobogo-grid-gap: var(--cobogo-space-group)"
>
  <article style="--cobogo-grid-span: 12; --cobogo-grid-span-md: 6; --cobogo-grid-span-lg: 4">
    ...
  </article>
  <article style="--cobogo-grid-span: 12; --cobogo-grid-span-md: 6; --cobogo-grid-span-lg: 4">
    ...
  </article>
  <article style="--cobogo-grid-span: 12; --cobogo-grid-span-md: 12; --cobogo-grid-span-lg: 4">
    ...
  </article>
</section>
```

## Número de colunas e gap

O padrão usa 12 colunas por default. Quando o problema pedir outra grade, altere `--cobogo-grid-columns`. O gap default é o papel semântico `--cobogo-space-group`.

```html
<div
  data-cobogo-pattern="grid"
  style="--cobogo-grid-columns: 4; --cobogo-grid-gap: var(--cobogo-space-adjacent)"
>
  ...
</div>
```

## Spans responsivos

Os filhos diretos herdam a quantidade de colunas do grid. Para alterar a ocupação, use:

| Custom property | Faixa | Papel |
| :--- | :--- | :--- |
| `--cobogo-grid-span` | base | span inicial |
| `--cobogo-grid-span-sm` | `>= 480px` | override pequeno |
| `--cobogo-grid-span-md` | `>= 768px` | override médio |
| `--cobogo-grid-span-lg` | `>= 1024px` | override grande |
| `--cobogo-grid-start` | todas | linha inicial opcional |

Cada faixa cai para o valor anterior quando não há override. Assim, normalmente basta declarar somente os pontos em que a composição realmente muda.

## Offset

```html
<section data-cobogo-pattern="grid">
  <article style="--cobogo-grid-span: 8; --cobogo-grid-start: 3">
    Conteúdo centralizado em oito colunas.
  </article>
</section>
```

## Semântica antes do wrapper

Use `section`, `article`, `main`, `form`, `fieldset` ou qualquer elemento que represente o conteúdo. O pattern não precisa de uma prop `as` porque não cria elemento algum.

Essa é a regra de simplificação aplicada aqui: quando Cobogó só precisa ensinar uma relação visual que CSS já representa bem, essa relação deve viver em CSS/HTML e não em um componente de framework.
